What are we creating?

👩‍🎓 Browser → 🌐 AWS Amplify Hosting → ⚡ Lambda Function URL → 🐍 AWS Lambda → 🗃️ DynamoDB

IAM controls what Lambda can do inside the AWS account. CloudWatch records logs for troubleshooting.

STEP 01 / 10

Before you start

Open an AWS account, select one AWS Region for all resources, and redeem a voucher if your account supports promotional credits. Never share voucher codes or account passwords. Use a sandbox or personal learning account only.

Open AWS Console ↗

STEP 02 / 10

Create the DynamoDB table

Open DynamoDB → Tables → Create table. Table name: StudentGuestbook. Partition key: messageId (String). Leave sort key empty. Choose On-demand capacity if available, retain defaults, then Create table. Copy the Table ARN from Additional info.

Open AWS Console ↗

STEP 03 / 10

Create a Python Lambda function

Open Lambda → Create function → Author from scratch. Name: student-guestbook-api. Choose Python 3.13 runtime (or supported Python runtime), create a new execution role with basic Lambda permissions. Create. In Code tab replace lambda_function.py with the backend file contents, then click Deploy.

Open AWS Console ↗

Show Python Lambda code
STEP 04 / 10

Give Lambda database permission

Lambda → Configuration → Permissions → click the role name to open IAM. Permissions → Add permissions → Create inline policy → JSON. Paste the included IAM policy, replacing the ARN placeholder with your DynamoDB table ARN. Name it GuestbookDynamoDBAccess and save.

Open AWS Console ↗

Show IAM policy template
STEP 05 / 10

Test Lambda without a website

Lambda → Test → Create new event. Paste test-post-event.json and run. Expect statusCode 201. Repeat with test-get-event.json and expect statusCode 200 and a messages array. If not, check table name, Region, role policy and CloudWatch logs.

Open AWS Console ↗

Show POST test event
Show GET test event
STEP 06 / 10

Make an HTTPS Function URL

Lambda → Configuration → Function URL → Create. Auth type NONE for this short public workshop demo ONLY. Configure CORS: Allowed origins *; allowed methods GET and POST; allowed headers Content-Type. Save. Copy the HTTPS Function URL. Confirm the generated resource policy allows public invoke in your account. If your organization blocks public URLs, use an authorized workshop account.

Open AWS Console ↗

STEP 07 / 10

Connect the website to Lambda

Download the Frontend ZIP from this guide and unzip it. Open config.js in Notepad or VS Code. Replace PASTE_YOUR_LAMBDA_FUNCTION_URL_HERE with the actual full HTTPS URL in quotes. Save. Select index.html, style.css, app.js and config.js and ZIP those four files at the ZIP root (not the parent folder).

STEP 08 / 10

Publish the frontend with Amplify

AWS Amplify → Create new app → Deploy without Git → Next. App name: student-guestbook. Branch: main. Method: Drag and drop. Upload the ZIP of the four frontend files, then Save and deploy. Wait for deployment to finish.

Open AWS Console ↗

STEP 09 / 10

Show the full-stack magic

Open the Amplify URL. Post a harmless test message (do not enter personal data). Refresh; open DynamoDB → Explore items and find your message. Exchange website URLs with a classmate to see their site.

STEP 10 / 10

Clean up after the workshop

Delete the Amplify app (not just close the browser). Delete Lambda function student-guestbook-api. Delete DynamoDB table StudentGuestbook. Delete any custom CloudWatch log group if desired. Verify resources are gone. Check billing over the next days.

Open AWS Console ↗
