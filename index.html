Build & Deploy a Serverless Website

Build a Cloud Guestbook using Amplify Hosting, API Gateway HTTP API, two Lambda functions, IAM and DynamoDB. Follow each step, copy the code and build along with the instructor.

Architecture

The browser calls API Gateway. The Lambda Authorizer checks Basic Authentication. If approved, API Gateway invokes the Guestbook Lambda, which reads or writes messages in DynamoDB.

1. Create the DynamoDB table · 7 min

DynamoDB stores the guestbook messages. A partition key and sort key let us retrieve the newest messages first.

  1. Open the DynamoDB console: https://console.aws.amazon.com/dynamodbv2/home?region=ap-southeast-1#tables
  2. Choose Create table. Table name: GuestbookMessages.
  3. Partition key: pk (String). Add sort key: messageId (String).
  4. Choose On-demand (PAY_PER_REQUEST) capacity mode. Leave other settings at their defaults and create the table.
  5. Wait for status Active. Open the table overview and copy the table ARN; you will use it in Step 3.
Guestbook Lambda — Python
import base64
import json
import logging
import os
import uuid
from datetime import datetime, timezone

import boto3
from boto3.dynamodb.conditions import Key

logger = logging.getLogger()
logger.setLevel(logging.INFO)

table = boto3.resource("dynamodb").Table(os.environ["TABLE_NAME"])


def response(status, body):
    return {
        "statusCode": status,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps(body),
    }


def lambda_handler(event, context):
    try:
        method = event.get("requestContext", {}).get("http", {}).get("method", "")

        if method == "GET":
            result = table.query(
                KeyConditionExpression=Key("pk").eq("GUESTBOOK"),
                ScanIndexForward=False,
                Limit=50,
            )
            messages = [
                {
                    "username": item.get("username", "Student"),
                    "message": item.get("message", ""),
                    "createdAt": item.get("createdAt", ""),
                }
                for item in result.get("Items", [])
            ]
            return response(200, {"messages": messages})

        if method == "POST":
            body_text = event.get("body") or "{}"
            if event.get("isBase64Encoded"):
                body_text = base64.b64decode(body_text).decode("utf-8")
            try:
                body = json.loads(body_text)
            except json.JSONDecodeError:
                return response(400, {"error": "Request body must be valid JSON."})

            message = str(body.get("message", "")).strip()
            if not message:
                return response(400, {"error": "Please enter a message."})
            if len(message) > 280:
                return response(400, {"error": "Message must be 280 characters or fewer."})

            auth_context = (
                event.get("requestContext", {})
                .get("authorizer", {})
                .get("lambda", {})
            )
            username = str(auth_context.get("username", "Student")).strip()[:40] or "Student"

            created_at = datetime.now(timezone.utc).isoformat(timespec="microseconds")
            message_id = created_at + "#" + uuid.uuid4().hex
            item = {
                "pk": "GUESTBOOK",
                "messageId": message_id,
                "username": username,
                "message": message,
                "createdAt": created_at,
            }
            table.put_item(Item=item)
            return response(201, {
                "message": "Your message has been saved.",
                "item": {
                    "username": username,
                    "message": message,
                    "createdAt": created_at,
                },
            })

        return response(404, {"error": "Route not found."})

    except Exception:
        logger.exception("Guestbook request failed")
        return response(500, {"error": "Something went wrong. Check the Lambda logs."})
Every row uses pk = GUESTBOOK. The messageId sort key contains a timestamp and unique ID, so Query can return newest messages first.

2. Create the Guestbook Lambda · 8 min

This Lambda contains the application logic. API Gateway invokes it only after the authorizer approves a request.

  1. Open Lambda: https://console.aws.amazon.com/lambda/home?region=ap-southeast-1#/functions
  2. Choose Create function → Author from scratch. Name: student-guestbook-api.
  3. Runtime: Python 3.12. Architecture: x86_64.
  4. For permissions, choose Create a new role with basic Lambda permissions. Create the function.
  5. In the Code tab, open lambda_function.py. Replace its contents with backend/guestbook_lambda.py from the ZIP. Choose Deploy.
  6. Open Configuration → Environment variables → Edit. Add TABLE_NAME = GuestbookMessages. Save.
IAM inline policy — JSON (replace the ARN)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "GuestbookTableAccess",
      "Effect": "Allow",
      "Action": [
        "dynamodb:PutItem",
        "dynamodb:Query"
      ],
      "Resource": "PASTE_THE_GUESTBOOK_TABLE_ARN_HERE"
    }
  ]
}
The Lambda supports GET /messages (query latest 50) and POST /messages (save a message).

3. Give the application Lambda DynamoDB access · 5 min

IAM controls which AWS resources the Lambda function can access. Grant only Query and PutItem on this table.

  1. In the Guestbook Lambda page, open Configuration → Permissions.
  2. Under Execution role, click the role name. In IAM, choose Add permissions → Create inline policy → JSON.
  3. Open iam/dynamodb-access-policy.json from the ZIP and paste it into the JSON editor.
  4. Replace PASTE_THE_GUESTBOOK_TABLE_ARN_HERE with the exact ARN copied in Step 1.
  5. Choose Next. Policy name: GuestbookTableAccess. Create the policy.
Lambda Authorizer — Python
import base64
import binascii
import hmac
import os

EXPECTED_PASSWORD = os.environ.get("DEMO_PASSWORD", "")


def deny():
    return {"isAuthorized": False}


def lambda_handler(event, context):
    headers = event.get("headers") or {}
    authorization = headers.get("authorization") or headers.get("Authorization")

    if not authorization or not EXPECTED_PASSWORD:
        return deny()

    scheme, separator, encoded = authorization.partition(" ")
    if not separator or scheme.lower() != "basic" or not encoded:
        return deny()

    try:
        decoded = base64.b64decode(encoded, validate=True).decode("utf-8")
    except (binascii.Error, UnicodeDecodeError, ValueError):
        return deny()

    username, colon, supplied_password = decoded.partition(":")
    username = username.strip()

    if not colon or not username or len(username) > 40:
        return deny()

    # Workshop demo: username is a display label; the class shares one temporary passphrase.
    if not hmac.compare_digest(supplied_password, EXPECTED_PASSWORD):
        return deny()

    return {
        "isAuthorized": True,
        "context": {"username": username},
    }
Do not use Resource = * for this exercise. The policy should refer to the single GuestbookMessages table.

4. Create the Lambda Authorizer · 6 min

The authorizer checks the HTTP Authorization header before API Gateway invokes the application Lambda.

  1. In Lambda, choose Create function → Author from scratch. Name: student-guestbook-authorizer.
  2. Runtime: Python 3.12. Architecture: x86_64. Create a new role with basic Lambda permissions.
  3. Create the function. Open Configuration → Environment variables → Edit.
  4. Add DEMO_PASSWORD and set it to the temporary class passphrase agreed with the instructor. Save.
  5. In the Code tab, replace lambda_function.py with authorizer/authorizer.py from the ZIP. Choose Deploy.
Classroom-only shortcut: any non-empty username is accepted when the shared temporary passphrase matches. The username is only a display name, not a verified identity. Do not use real user data or personal passwords.

5. Create the API Gateway HTTP API · 7 min

API Gateway is the public front door. Use HTTP API, not REST API, to keep this beginner lab short.

  1. Open API Gateway: https://console.aws.amazon.com/apigateway/main/apis?region=ap-southeast-1
  2. Choose Create API. Under HTTP API, choose Build.
  3. Add an integration: Lambda → student-guestbook-api in the same Region.
  4. API name: student-guestbook-http-api. Review and create.
  5. Open Routes. Create GET /messages and POST /messages. Set both routes to the student-guestbook-api integration.
  6. Open Stages. Use the $default stage and enable Auto-deploy. If it does not exist, create it.
  7. Copy the API invoke URL. It looks like https://abc123.execute-api.ap-southeast-1.amazonaws.com. Keep it for Step 7.
With the $default stage, the API URL has no stage suffix. Do not add /prod or /messages to the base URL.

6. Configure the Lambda Authorizer · 8 min

Use HTTP API payload format 2.0 and simple responses. This avoids writing an IAM policy document in the authorizer code.

  1. In the HTTP API, open Authorization or Authorizers (the console label may vary). Choose Manage authorizers → Create.
  2. Type: Lambda. Name: student-basic-authorizer. Lambda function: student-guestbook-authorizer.
  3. Payload format version: 2.0. Enable Simple responses.
  4. Identity source: $request.header.Authorization.
  5. Authorizer result TTL: 0 seconds (disable caching for this workshop). Save/create.
  6. If prompted, allow API Gateway to invoke the authorizer Lambda.
  7. Open Routes. Edit GET /messages and attach student-basic-authorizer. Repeat for POST /messages.
  8. Confirm both routes require the authorizer.
No Authorization header → API Gateway returns 401 without invoking the authorizer. Wrong passphrase → authorizer denies the request. Correct passphrase → Guestbook Lambda runs.

7. Set the API URL in the frontend · 3 min

The frontend needs the API Gateway invoke URL.

  1. Open frontend/app.js in Notepad or another text editor.
  2. Find PASTE_YOUR_API_GATEWAY_INVOKE_URL_HERE.
  3. Replace it with your API invoke URL from Step 5. Keep the quotation marks. Do not append /messages.
  4. Save the file.
Example: const API_BASE_URL = "https://YOUR_API_ID.execute-api.ap-southeast-1.amazonaws.com".replace(/\/$/, "");

8. Deploy the website with Amplify Hosting · 7 min

Amplify publishes the static website and gives it a public HTTPS URL. No Git, Node.js or AWS CLI is required.

  1. Create a ZIP containing index.html, style.css and app.js at the ZIP root. Do not ZIP the parent frontend folder.
  2. Open Amplify: https://console.aws.amazon.com/amplify/home?region=ap-southeast-1
  3. Choose Create new app → Deploy without Git → Next.
  4. App name: student-cloud-guestbook. Branch name: main. Method: Drag and drop.
  5. Upload the ZIP and choose Save and deploy.
  6. When deployment completes, open the Amplify URL and copy its origin only, e.g. https://main.xxxxx.amplifyapp.com.
The ZIP must contain the site files at its root. If you change app.js after creating the ZIP, create a new ZIP and redeploy.

9. Configure CORS in API Gateway · 4 min

CORS lets the browser website call an API hosted on a different domain. Allow only your Amplify website origin.

  1. Return to API Gateway and open your HTTP API → CORS.
  2. Allowed origins: paste the exact Amplify origin (include https://; no trailing slash).
  3. Allowed methods: GET, POST, OPTIONS.
  4. Allowed headers: authorization, content-type.
  5. Leave Allow credentials disabled. The frontend sends the Authorization header itself and does not use cookies.
  6. Save. The $default auto-deploy stage publishes the change.
API Gateway automatically handles preflight OPTIONS requests when CORS is configured. Do not create an authenticated OPTIONS route.

10. Test the application · 8 min

Test successful authentication, failed authentication, writing, reading and sharing.

  1. Open your Amplify website. Enter your display name and the class passphrase. Choose Sign in.
  2. Confirm the guestbook loads. This request calls GET /messages with the Basic Authorization header.
  3. Post: I deployed my first serverless website! Confirm it appears in Recent messages.
  4. Open DynamoDB → Tables → GuestbookMessages → Explore table items. Confirm the message is stored.
  5. Ask a partner to open your Amplify URL and sign in using their own display name and the same temporary class passphrase. They should be able to post to your guestbook.
  6. Try an incorrect passphrase; it should be rejected. Choose Log out and refresh; you should need to sign in again.
Success means the website loads, valid credentials work, invalid credentials fail, messages are stored in DynamoDB, and another student can post.

11. View CloudWatch logs · optional

CloudWatch Logs helps troubleshoot the two Lambda functions.

  1. Open CloudWatch → Logs → Log groups.
  2. Inspect /aws/lambda/student-guestbook-api for application logs.
  3. Inspect /aws/lambda/student-guestbook-authorizer for authorizer logs.
  4. Never log Authorization headers, passwords or Base64 credentials.
If the API returns 500, check whether API Gateway has permission to invoke the relevant Lambda and inspect its CloudWatch logs.

Troubleshooting

401 Unauthorized

The Authorization header is missing. Check the frontend API URL and the authorizer identity source: $request.header.Authorization.

403 Forbidden

The request reached the authorizer but the passphrase was rejected. Check the DEMO_PASSWORD environment variable and the class passphrase.

CORS error in browser

Check the exact Amplify origin, allowed methods GET/POST/OPTIONS, and allowed headers authorization/content-type. Do not include a trailing slash in the origin.

500 from API Gateway

Check that API Gateway has permission to invoke both Lambda functions. Inspect each Lambda's Configuration → Permissions and CloudWatch logs.

DynamoDB AccessDeniedException

Check TABLE_NAME and the application Lambda execution role's Query/PutItem policy. The Resource must be the exact table ARN.

Amplify Access Denied

The ZIP must contain index.html, style.css and app.js at its root, not inside a parent folder.

API URL does not work

Use the API Gateway invoke URL for the $default stage. Do not append /prod or /messages to API_BASE_URL.
